# M1. Delegate file renaming to an agent

## Goal
- Delegate a job to Codex while **restricting it to one folder**.
- Review the agent's **plan (dry-run table)** before it acts, fix the mistakes yourself, and only then approve.
- Check the result with a **verification tool**. ("Done" is judged by the checker, not by the agent's claim.)

## You need
- M0 done (`~/agent-lab/m1` messy folder with an initial git commit)

## Steps
1. First look at the folder yourself (`ls ~/agent-lab/m1`). Note 3 files whose rule looks ambiguous.
2. Start Codex **locked to this folder**:
   ```bash
   codex --cd ~/agent-lab/m1 --sandbox workspace-write
   ```
3. Paste the prompt below (English or Japanese version; you may also adapt it).
4. When the agent shows the table (old -> new), **while it is still not allowed to act**, review it line by line. If a row is wrong (date reading, version, extension...), tell the agent which row is wrong and why.
5. When you think the table is correct, answer "Approved. Go ahead." (or 「承認します。進めてください。」).
6. Quit Codex (`/quit` or Ctrl+C) and verify:
   ```bash
   python3 ~/AI-Agent-Tutorial/tools/check_mission.py m1 ~/agent-lab/m1
   ```
   If it fails, read "examples of mistakes" in the output and ask Codex to fix them.
7. Record the result in git:
   ```bash
   cd ~/agent-lab/m1 && git add -A && git commit -m "M1: rename to canonical names" && git log --oneline
   ```

## Prompt for the agent
You may write your own prompt in Japanese or English. Keep these explicit: the name rule, "show the table first", "wait for my approval", "never delete or modify".

### English
```text
This folder (the current working directory) contains about 60 experiment files with inconsistent names.
Rename every file to the canonical name below.

Canonical name: <kind>_run<NNN>_<YYYYMMDD>_v<N>.<lowercase extension>
- kind is decided by the extension: .csv -> data, .txt -> scope, .png -> plot, .md -> note
- NNN is the run number zero-padded to 3 digits (Run12, run_012, R12, run-12 all mean 12 -> 012)
- Several date formats are mixed (e.g. 20261103, 2026-11-03, 03Nov2026, 11_03_2026 which is MM_DD_YYYY).
- N is the number in the name written as v1..v3 (v2 -> 2)
- Words like final, new, copy and "(2)" are meaningless noise; ignore them.
- If a name has no date, open the file and use the first line "# date: YYYY-MM-DD".
- If the information cannot be determined, do not guess: move the file to _unsorted/ and keep its original name.

Rules you must follow:
1. First change nothing; only show me the "old -> new" table. For files where you had to make a judgement, add a one-line reason.
2. Do not rename anything until I say "approved".
3. Never modify file contents and never delete any file. Never touch hidden files/folders whose name starts with "." (.git, .mission.json, ...).
4. Do not create new files in this folder. If you need a script, put it in /tmp.
5. Do not touch anything outside this folder.
6. When finished, explain how you did it (mv per file, a script, ...).
```

### 日本語
```text
このフォルダ(現在の作業ディレクトリ)には、名前がバラバラな実験ファイルが約60個あります。
すべてのファイルを、下の規則の標準名に変更してください。

標準名: <kind>_run<NNN>_<YYYYMMDD>_v<N>.<小文字の拡張子>
- kind は拡張子で決める: .csv -> data, .txt -> scope, .png -> plot, .md -> note
- NNN は run 番号を3桁の0埋めにする (Run12, run_012, R12, run-12 はすべて 12 -> 012)
- 日付の書式は複数混在している (例: 20261103, 2026-11-03, 03Nov2026, 11_03_2026 は月_日_年)。
- N は名前の中の v1〜v3 の数字 (v2 -> 2)
- final, new, copy, "(2)" などの語は意味のないノイズなので無視する。
- 名前に日付がないファイルは、ファイルを開いて1行目の "# date: YYYY-MM-DD" を使う。
- どうしても情報が分からないファイルは推測せず、元の名前のまま _unsorted/ フォルダへ移す。

必ず守ること:
1. まず何も変更せず、「old -> new」の表だけを見せてください。判断が必要だったファイルには理由を1行で添えてください。
2. 私が「承認」と言うまで、名前を変更しないでください。
3. ファイルの内容を変更したり、ファイルを削除したりしないでください。名前が "." で始まる隠しファイル/フォルダ(.git, .mission.json など)には触れないでください。
4. このフォルダの中に新しいファイルを作らないでください。スクリプトが必要なら /tmp に作ってください。
5. このフォルダの外には触れないでください。
6. 終わったら、どの方法(ファイルごとの mv、スクリプトなど)で行ったか説明してください。
```

## Observe
- Did the agent run `mv` per file, or write a script and process everything at once? (watch the commands that run)
- How did it handle ambiguous files: no date, the `11_03_2026` format, `IMG_xxxx.png`? Did the table explain why?
- Did it really change nothing before approval? (check with `git status`)
- How did it react to the mistakes you found in the table?

## Done when
- `check_mission.py m1 ~/agent-lab/m1` ends with `RESULT / 結果: PASS` (accuracy ≥ 95%, no content lost or changed).

## If you are stuck
- The agent acted without approval: check `git status`, restore with `git checkout -- . && git clean -fd` (inside this folder only!), and try again with rules 1–2 stressed.
- Content FAIL → use `git diff` / `git status` to see what disappeared and restore it.
- Low accuracy → show the agent the "examples of mistakes" verbatim and ask it to re-read the rules and fix only those files.
- If Codex asks for permission, read it and decide. Refuse anything outside the folder.
