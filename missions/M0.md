# M0. Prepare your work environment

## Goal
- Confirm that Codex, git and Python work on your computer.
- Create the **work area** `~/agent-lab`; do all exercises only inside it.
- Generate the "messy folder" used in the next missions and record its starting state with git.

## You need
- A terminal. macOS: Terminal. **Windows: use WSL2 (Ubuntu), not PowerShell/CMD.** Type every command of this course in the Ubuntu terminal; `~` is your Linux home (in Explorer it is `\\wsl$\Ubuntu\home\<you>`; `explorer.exe .` opens the current folder).
- The tutorial repo cloned to `~/agent-tutorial` (step 1)
- Your student number (used as `<seed>` below; digits only, for example `2345`; if it is not a number, use its last 4 digits)
- A ChatGPT account (for the Codex login) and a GitHub account

## Steps
1. Get the tutorial files (this creates `~/agent-tutorial`):
   ```bash
   git clone https://github.com/BongHwi/agent-tutorial.git ~/agent-tutorial
   ls ~/agent-tutorial/tools/check_env.py     # must exist
   ```
2. Install Python 3.10+ and git if missing. Check: `python3 --version`, `git --version`.
3. Install the Codex CLI and log in. Follow the official docs (https://developers.openai.com/codex/cli). Typical routes: macOS `brew install --cask codex`; Linux/WSL install Node.js first (for example with `nvm`) and then `npm i -g @openai/codex`. Then `codex --version` and `codex login`. If no browser opens (WSL), run `codex login --device-auth` and enter the shown code in your Windows browser.
4. Run the environment check:
   ```bash
   python3 ~/agent-tutorial/tools/check_env.py
   ```
   There must be no `FAIL` (a missing Codex login is a `FAIL`: run `codex login` and check again). Only the `node` line may stay `WARN` for now (Node >= 24.9 is needed in week 2 for DSH).
5. Create the work area and the messy folder:
   ```bash
   mkdir -p ~/agent-lab
   python3 ~/agent-tutorial/tools/make_messy_folder.py --mission m1 --seed <seed> --out ~/agent-lab/m1
   ls ~/agent-lab/m1 | head
   ```
6. Record the starting state with git:
   ```bash
   cd ~/agent-lab/m1
   git init
   git add -A
   git commit -m "initial messy state"
   git log --oneline
   ```
   (The `hint:` lines git prints about branch names are harmless. If `git commit` asks for a name/email: `git config --global user.name "Your Name"` and `git config --global user.email "you@example.com"`, then retry.)
7. Create the submission repo (see README "How to submit" for the details): sign in to GitHub from your terminal (`gh auth login`, choose GitHub.com → HTTPS → web browser), create a **private** repo `agent-tutorial-<student number>` **with "Add a README file" ticked**, invite the instructor account `BongHwi` as collaborator, then `cd ~/agent-lab && git clone https://github.com/<your ID>/agent-tutorial-<student number>.git submission`.

## Observe
- How many files are in `~/agent-lab/m1`, and how inconsistent are the names? Can you find the rules?
- What could the first git commit be used for in later missions?

## Done when
- `check_env.py` output has no `FAIL`.
- `~/agent-lab/m1` has about 60 files plus the hidden file `.mission.json` (`ls -a` shows it; never move or delete it).
- `git log --oneline` shows 1 commit.
- `~/agent-lab/submission` is a clone of your GitHub repo.

## If you are stuck
- `python3: command not found` → install Python and open a new terminal.
- `codex: command not found` → open a new terminal after installing, or check your PATH.
- "`--out` folder is not empty" → remove it (`rm -rf ~/agent-lab/m1`, **exactly this path only**) and regenerate.
- `Authentication failed` on `git clone`/`git push` → run `gh auth login` (your GitHub password does not work for git; the alternative is a Personal Access Token with scope `repo`).
- Otherwise copy the whole error message and post it in the course's question channel (the instructor announces where).
- If you cannot finish, submit what you have (the `check_env.py` output and a note on what failed); partial work is better than nothing.

## Submit
Write `~/agent-lab/submission/M0.md` containing the full `check_env.py` output (within 10 lines, in a code block), then commit and push (README "How to submit").
