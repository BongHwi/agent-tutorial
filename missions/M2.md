# M2. Restructure a folder and build an undo

## Goal
- Delegate restructuring a flat folder into a date/run tree.
- Make the agent create its own **way back** (`moves.csv`, `undo.py`) and actually test going back.
- See whether the agent handles **traps** (exact duplicates, name collisions) safely. (No deletion!)

## You need
- M1 done (you already know how to use `check_mission.py`)

## Steps
1. Generate a new messy folder and record the starting state:
   ```bash
   python3 ~/agent-tutorial/tools/make_messy_folder.py --mission m2 --seed <seed> --out ~/agent-lab/m2
   cd ~/agent-lab/m2 && git init && git add -A && git commit -m "initial m2 state" && cd ~
   ```
2. Look around. There is a subfolder `laptop_copy/`. Some files have the same name but different content; some have different names but the same content. Think first about how you would find them. (Hint: `shasum -a 256 <file>` on macOS, `sha256sum <file>` on Linux/WSL)
3. Start Codex locked to this folder and paste the prompt:
   ```bash
   codex --cd ~/agent-lab/m2 --sandbox workspace-write
   ```
4. Review the plan table. Pay special attention to duplicates/collisions; ask for fixes if needed. Then approve.
5. Verify:
   ```bash
   python3 ~/agent-tutorial/tools/check_mission.py m2 ~/agent-lab/m2
   ```
6. **Undo test**:
   ```bash
   cd ~/agent-lab/m2
   python3 undo.py
   git status --short
   ```
   Exactly two lines must remain: `?? moves.csv` and `?? undo.py` (these two are new files, so they show as untracked; that is normal). Any modified/deleted entry means the undo is incomplete.
7. **Redo**: re-apply the old -> new moves of `moves.csv` (ask the agent, or write it yourself using `undo.py` as a model), then run `check_mission.py m2` again. Put any redo script **outside** the folder (for example `~/agent-lab/redo_m2.py`) and run it from inside `~/agent-lab/m2`: any extra file inside the folder makes the file count wrong.

## Prompt for the agent
You may write your own prompt in Japanese or English. Keep the explicit rules: dry-run first, wait for approval, no deletion, `moves.csv` columns `old,new`.

### English
```text
Restructure the roughly 60 experiment files in this folder (including those in the subfolder laptop_copy/) into the structure below.

Target structure: <YYYYMMDD>/run<NNN>/{raw,plots,notes}/
- Read the date and run number from names like data_run012_20261103_v1.csv.
- data(.csv), scope(.txt) -> raw/, plot(.png) -> plots/, note(.md) -> notes/
- Do not rename files; only move them.

Rules for the traps:
- Some files have exactly the same content under different names. Keep one in the target location and move the others to _duplicates/. Never delete them.
- Some files would end up with the same target path but have different content (a collision). Keep both; this is the only case where you may change a name: add a suffix (_2 etc.) to the one that comes from laptop_copy/.
- Decide whether content is the same by hash.

Rules you must follow:
1. First move nothing; show me the plan table (old -> new) and the list of duplicates/collisions you found. Do not move anything until I say "approved".
2. Do not modify contents and do not delete anything. Never touch hidden files/folders whose name starts with "." (.git, .mission.json, ...). Do not touch anything outside this folder. Do not create any file in this folder other than moves.csv and undo.py; if you need a helper script, put it in /tmp.
3. After approval, while moving, record every move in moves.csv directly in this folder (header: old,new; paths relative to this folder).
4. Also create undo.py directly in this folder. When run, it reads moves.csv, moves every file back to its original place, and removes folders that became empty.
5. Do not run undo.py yourself to test it. (I will check it.)
6. When finished, summarize how you handled duplicates and collisions.
```

### 日本語
```text
このフォルダ(サブフォルダ laptop_copy/ の中も含む)にある約60個の実験ファイルを、下の構造に再編してください。

目標の構造: <YYYYMMDD>/run<NNN>/{raw,plots,notes}/
- data_run012_20261103_v1.csv のような名前から、日付と run 番号を読み取る。
- data(.csv), scope(.txt) -> raw/、plot(.png) -> plots/、note(.md) -> notes/
- ファイル名は変えず、場所だけを移す。

わなの扱い:
- 名前は違うが内容がまったく同じファイルがある。1つだけを目標の場所に置き、残りは _duplicates/ に移す。絶対に削除しない。
- 目標の場所の名前が同じなのに内容が違うファイル(衝突)がある。両方とも残し、片方に接尾辞(_2 など)を付ける(名前を変えてよいのはこの場合だけ)。
- 内容が同じかどうかはハッシュで判断する。

必ず守ること:
1. まず何も移動せず、計画の表(old -> new)と、見つけた重複/衝突の一覧を見せてください。私が「承認」と言うまで移動しないでください。
2. 内容の変更・削除は禁止。名前が "." で始まる隠しファイル/フォルダ(.git, .mission.json など)には触れないでください。このフォルダの外にも触れないでください。このフォルダの中には moves.csv と undo.py 以外の新しいファイルを作らないでください。スクリプトが必要なら /tmp に作ってください。
3. 承認後、移動しながら、このフォルダ直下の moves.csv にすべての移動を記録してください(ヘッダー: old,new、このフォルダからの相対パス)。
4. このフォルダ直下に undo.py も作ってください。実行すると moves.csv を読み、すべてのファイルを元の場所に戻し、空になったフォルダを削除します。
5. undo.py をあなた自身で実行してテストしないでください。(私が確認します)
6. 終わったら、重複と衝突をどう処理したか要約してください。
```

## Observe
- How did the agent find duplicates (hash? size? name comparison?)
- What suffix rule did it use for collisions? Is it a good one (can you tell the files apart later)?
- Did `undo.py` work on the first try? If not, what was wrong (empty folders, paths, order)?
- Did the agent remove the emptied `laptop_copy/` folder? Does `undo.py` bring it back?
- Which sentence of your prompt influenced the result the most?

## Done when
- `check_mission.py m2 ~/agent-lab/m2` shows `RESULT / 結果: PASS`
- after `python3 undo.py`, `git status --short` shows only `?? moves.csv` and `?? undo.py`
- after redo, `check_mission.py m2` is PASS again

## If you are stuck
- Files remain after undo → check `git status`, tell the agent what is wrong with `undo.py`, ask for a fix.
- Everything is a mess → inside this folder run `git checkout -- . && git clean -fd` to restore the start, then begin again.
- If the `moves.csv` header is not `old,new` the checker fails. Tell the agent the exact column names again.
- `0/60 valid rows` → paths in `moves.csv` must be relative to the folder, with no `./` and no absolute paths.
- `file count 61/60` → the checker lists the unexpected files; remove them from the folder (helper scripts belong in `/tmp`).
