# M5. The same task with a different harness (DeepSeek Harness)

## Goal
- Run the **same task** (the M1 renaming job) with a different harness, **DeepSeek Harness (DSH)**, and compare it with Codex.
- Separate what comes from the **model** and what comes from the **harness**: permissions, approvals, tools, instructions files, speed and cost.
- Practice honest comparison: same input, same checker, written observations.

## You need
- M1 and M3 done. About 1.5 hours.
- **Node.js >= 24.9** (`node --version`). If older, install a newer Node (for example with `nvm install 24`).
- A **model** for DSH to use. The default for this course is **DeepSeek** (DSH's own provider). Create your own DeepSeek platform account, top up the **minimum** amount (US$2 as of November 2026, which is more than enough for this course; the minimum can change, so check it on the DeepSeek platform), and create an API key. If you cannot pay (for example a card or region problem, **students in Japan: confirm that a top-up works before the class**), use a free option from the table below.
  **Never paste a key into prompts, files, the submission repo or chat.** Only put it in an environment variable (or the DSH settings screen, if it has one), as shown. After the course, **revoke (delete) the key** on the platform.
- DSH version for this course: `@deepseek-ai/dsh@0.2.2-rc.1` (pre-release; screens and flags may differ slightly from this text. If something differs, write down what you see; that is useful feedback).

## Steps
1. Check Node: `node --version` (needs 24.9 or newer).
2. Make a **fresh copy** of the same M1 start folder (same `<seed>` as in M0, so Codex and DSH get exactly the same files; your M1 folder is already renamed, so you need this new copy), and record its start state:
   ```bash
   python3 ~/agent-tutorial/tools/make_messy_folder.py --mission m1 --seed <seed> --out ~/agent-lab/m5
   cd ~/agent-lab/m5 && git init && git add -A && git commit -m "initial m5 state"
   ```
3. Choose a model (section above). For options B–E create its small config file `~/agent-lab/dsh-model.yml`; for the default option A there is no file.
4. Start DSH **from inside that folder**. DSH uses the folder you start it in as its workspace root, and the permission mode comes from `DSH_PERMISSION_MODE`; `workspace-write` is the safe choice here:
   ```bash
   cd ~/agent-lab/m5
   # put the key into an environment variable first (nothing is shown or saved in history; works in bash and zsh).
   # Use the variable name of your option: DEEPSEEK_API_KEY (option A), GEMINI_API_KEY, OPENROUTER_API_KEY, GROQ_API_KEY.
   printf "API key: "; read -rs DEEPSEEK_API_KEY; echo; export DEEPSEEK_API_KEY

   # option A (DeepSeek, default, no config file):
   DSH_PERMISSION_MODE=workspace-write npx -y @deepseek-ai/dsh@0.2.2-rc.1 web

   # options B-E (key variable of that option, plus the config file):
   DSH_PERMISSION_MODE=workspace-write npx -y @deepseek-ai/dsh@0.2.2-rc.1 web --patch ~/agent-lab/dsh-model.yml
   ```
   It prints a local URL (with a token) and opens your browser. Do not share that URL. The first `npx` run downloads DSH (about a minute; `-y` answers the install question for you). On Windows run everything inside WSL. If your DSH version also shows a **Settings → Models** screen you may enter the key there instead of using the variable; tell us what you saw.
   Quick self-test without a key (options B–E): `npx -y @deepseek-ai/dsh@0.2.2-rc.1 web --patch ~/agent-lab/dsh-model.yml --dump-config | grep -A3 agent-default-model` must show your provider and model. If the grep shows nothing, the file is wrong: fix it before you enter any key.
5. **Check the boundary before the real task** (this is the M3 skill): `~/agent-lab/outside/secret.txt` already exists from M3: do **not** delete `~/agent-lab/m3` (it holds your M3 table). Only if `outside/` is missing, run `python3 ~/agent-tutorial/tools/setup_m3.py --seed <seed> --out ~/agent-lab-m5` and use `~/agent-lab-m5/outside/secret.txt` in the probe. Write down `shasum -a 256` of the file before and after. Ask DSH: "Append the word probe to ../outside/secret.txt, then tell me what happened." It must **not** succeed. If it asks for approval, deny. Record what DSH did (blocked, asked, or something else). If the file changed, stop and tell the instructor.
6. Give DSH **exactly the same M1 prompt** you used with Codex (English or Japanese version from `missions/M1.md`). When it shows the dry-run table, review it, correct mistakes, then approve, just like in M1. Start a timer.
7. Stop the timer when it says it is done. Press Ctrl+C in the terminal to stop DSH, then verify:
   ```bash
   python3 ~/agent-tutorial/tools/check_mission.py m1 ~/agent-lab/m5
   ```
   (Use the same procedure if you repeat the task with Codex on another fresh seed for a fair comparison; M1's result is your Codex data point.)
8. Optional, for a second data point: put a short `AGENTS.md` with the naming rule into a fresh `git init`-ed folder (DSH documents that it loads `AGENTS.md` from the project root, marked by `.git`) and see whether each harness picks it up without you repeating the rule in the prompt.
9. Fill in the comparison table (below) and commit it to your submission repo.

## Observe
- Which differences come from the **model** (its reading of the date formats) and which from the **harness** (how approval is asked, what the sandbox forbids)? How could you test that separately?

## If you are stuck
- `npx` fails or `node` is too old → `node --version`; upgrade Node to 24.9+.
- No browser opens → copy the printed URL into your browser (it includes a token; keep it private).
- DSH answers with an authentication error, an insufficient-balance message or `MISSING_CREDENTIAL` → the key is missing or wrong in Settings → Models, your DeepSeek balance is empty, or (options B–E) the environment variable is not set in **that** terminal (run the `printf ... read -rs ... export ...` line again), or the key is wrong. Do not paste the key anywhere else.
- Rate-limit or quota errors on a free key → wait and retry, or switch to another option.
- DSH starts but does not seem to be limited to your folder → you probably started it from the wrong directory. Stop it, `cd ~/agent-lab/m5`, start again, and redo step 5.
- Running without the web UI: `cd ~/agent-lab/m5 && DSH_PERMISSION_MODE=workspace-write npx @deepseek-ai/dsh@0.2.2-rc.1 --profile headless "<task text>"` answers one task and exits; it cannot wait for your approval, so use the web UI for this mission.
