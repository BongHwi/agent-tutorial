# M4. Turn the cleanup into a reusable tool

## Goal
- Stop repeating a task by hand: have Codex build a **tool** (`organize.py`) that does the M1 renaming job by itself, safely.
- Give the agent **standing instructions** in an `AGENTS.md` file so you do not have to repeat the rules in every prompt.
- Make the tool **verifiable**: it comes with its own tests, and the checker runs it on folders it has never seen.

## You need
- M1 done (you know the naming rule and `check_mission.py m1`)
- pytest for the same Python you use for the tools: `python3 -m pip install pytest` (do not use a bare `pip install`, it may install into another Python)

## Steps
1. Create a project folder and start its git history:
   ```bash
   mkdir -p ~/agent-lab/organizer && cd ~/agent-lab/organizer && git init
   ```
2. Start Codex locked to the project folder: `codex --cd ~/agent-lab/organizer --sandbox workspace-write`
3. Paste the prompt below. The agent should create `AGENTS.md`, `organize.py` and `tests/`. Read what it wrote.
4. The tool will be graded on **fresh** messy folders. Create one yourself to try it, anywhere inside `~/agent-lab`:
   ```bash
   python3 ~/agent-tutorial/tools/make_messy_folder.py --mission m1 --seed 4242 --out ~/agent-lab/try1
   python3 ~/agent-lab/organizer/organize.py ~/agent-lab/try1            # dry run: prints the plan, changes nothing
   python3 ~/agent-lab/organizer/organize.py ~/agent-lab/try1 --apply    # does it
   python3 ~/agent-tutorial/tools/check_mission.py m1 ~/agent-lab/try1
   ```
5. Run the tool's own tests: `cd ~/agent-lab/organizer && python3 -m pytest -q`. Read the tests: do they test real behaviour (dry run changes nothing, ambiguous files, no deletion), or only trivial things?
6. Improve through feedback: when something fails, give the agent the **failing output**, not a vague complaint.
7. Run the grader (it uses 3 new random seeds each time, so a tool that memorised answers will fail):
   ```bash
   python3 ~/agent-tutorial/tools/check_m4.py ~/agent-lab/organizer
   ```
8. Commit (first ignore cache folders): `printf '__pycache__/\n.pytest_cache/\n' > .gitignore && git add -A && git commit -m "M4: organize tool" && git log --oneline`.

## Prompt for the agent
### English
```text
Build a reusable command-line tool in this folder (the current working directory). Create exactly these files: AGENTS.md, organize.py, tests/test_organize.py. Use only the Python standard library (pytest for tests).

Job of the tool: rename the experiment files of a messy folder to canonical names.
  python3 organize.py FOLDER            # dry run (default): print a table "old -> new" and change NOTHING
  python3 organize.py FOLDER --apply    # perform the renames and write FOLDER/moves.csv with header old,new

Canonical name: <kind>_run<NNN>_<YYYYMMDD>_v<N>.<lowercase extension>
- kind from the extension: .csv -> data, .txt -> scope, .png -> plot, .md -> note
- NNN is the run number zero-padded to 3 digits (Run12, run_012, R12, run-12 -> 012)
- dates appear in several formats (20261103, 2026-11-03, 03Nov2026, 11_03_2026 = MM_DD_YYYY)
- N is the number of the v1..v3 token in the name
- words like final, new, copy and "(2)" are noise; ignore them
- if a name has no date, use the first line "# date: YYYY-MM-DD" of the file
- if the information cannot be determined, do not guess: move the file to FOLDER/_unsorted/ with its original name

Hard requirements:
- Never delete or overwrite any file and never modify file contents. Stop with an error instead of overwriting if two files would get the same new name.
- Never touch hidden files or folders (names starting with "."), and never touch anything outside FOLDER.
- The tool must run without any interactive input.
- AGENTS.md must contain the naming rule above and the rule "never delete or overwrite files; dry run is the default".
- tests/test_organize.py must test the behaviour with temporary folders (name parsing for every date/run format, dry run changes nothing, --apply writes moves.csv, a file without date uses its first line, an unknown file goes to _unsorted/, nothing is ever deleted, collisions stop with an error). Run the tests and fix failures.
When finished, show the test output and tell me which cases you were unsure about.
```

### 日本語
```text
このフォルダ(現在の作業ディレクトリ)に、再利用できるコマンドラインツールを作ってください。作るファイルは次の3つだけです: AGENTS.md, organize.py, tests/test_organize.py。Python標準ライブラリのみ使用(テストには pytest を使う)。

ツールの仕事: 散らかったフォルダの実験ファイルを標準名に変更すること。
  python3 organize.py FOLDER            # ドライラン(デフォルト): 「old -> new」の表を表示し、何も変更しない
  python3 organize.py FOLDER --apply    # 実際に名前を変更し、FOLDER/moves.csv(ヘッダー old,new)を書く

標準名: <kind>_run<NNN>_<YYYYMMDD>_v<N>.<小文字の拡張子>
- kind は拡張子で決める: .csv -> data, .txt -> scope, .png -> plot, .md -> note
- NNN は run 番号を3桁の0埋め (Run12, run_012, R12, run-12 -> 012)
- 日付は複数の書式がある (20261103, 2026-11-03, 03Nov2026, 11_03_2026 は月_日_年)
- N は名前の中の v1〜v3 の数字
- final, new, copy, "(2)" などはノイズなので無視する
- 名前に日付がなければ、ファイルの1行目 "# date: YYYY-MM-DD" を使う
- 情報が分からないファイルは推測せず、元の名前のまま FOLDER/_unsorted/ に移す

必須要件:
- ファイルを削除・上書きしない。内容も変更しない。2つのファイルが同じ新しい名前になる場合は、上書きせずエラーで止まる。
- 隠しファイル/フォルダ(名前が "." で始まるもの)と FOLDER の外には触れない。
- ツールは対話入力なしで動くこと。
- AGENTS.md には上の命名規則と「ファイルを削除・上書きしない。ドライランがデフォルト」というルールを書くこと。
- tests/test_organize.py は一時フォルダで動作をテストすること(すべての日付/run の書式の解析、ドライランが何も変更しないこと、--apply が moves.csv を書くこと、日付のないファイルが1行目を使うこと、不明なファイルが _unsorted/ に行くこと、何も削除されないこと、衝突でエラー停止すること)。テストを実行して失敗を直してください。
終わったら、テストの出力を見せて、判断に迷ったケースを教えてください。
```

## Observe
- Did the agent put the rules into `AGENTS.md` itself? In M1 you retyped the rules in each prompt; what changes now that they live in a file?
- Open the tests. Which important cases are missing? (Add one yourself and see whether the tool survives.)
- First grader run: did all 3 fresh seeds pass? If not, what kind of file broke the tool?
- Compare: the agent renaming files in M1 vs the agent writing a tool that renames files. Which is easier to verify, and why?

## Done when
- `check_m4.py ~/agent-lab/organizer` shows `RESULT / 結果: PASS`: `AGENTS.md` has the rules, 3 fresh seeds pass (dry run changes nothing, `--apply` produces correct names and `moves.csv`, nothing lost), and your own `pytest` passes.

## If you are stuck
- Grader says the dry run changed the folder → ask the agent to make dry run the default and to apply only with `--apply`; show it the grader line.
- Grader says "timed out" → the tool waits for input (for example a confirmation prompt); it must run non-interactively.
- A seed fails on a single odd file → regenerate that seed (`python3 ~/agent-tutorial/tools/make_messy_folder.py --mission m1 --seed N --out ~/agent-lab/tryN`), run the tool on it yourself, and show the agent the exact old name and expected name from the checker's "examples of mistakes".
- Tests pass but the grader fails → the tests are too weak. Ask for tests that use the failing file's pattern.
